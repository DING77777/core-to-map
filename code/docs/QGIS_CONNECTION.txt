Using HyLogger results in QGIS
15 October 2026

The same online imagery and exported query results can be opened in QGIS. A fully linked native plugin would require a separate interface adapter and has not been implemented.
QGIS is a free, open-source desktop GIS. A local plugin does not require a purchased developer licence or prior publication in the official repository. Basemap and drillhole data retain their own terms.

1. Connect the aerial basemap

File: code/docs/qgis_landgate_wms.xml
It stores a connection name and URL only. It contains no images, accounts or drillhole data, and does not install a plugin.

1. In QGIS, choose Layer > Add Layer > Add WMS/WMTS Layer.
2. Click Load, select qgis_landgate_wms.xml and import its Landgate connection.
3. Select the connection and click Connect.
4. Find the Locate imagery layer and check that its Name/ID is 1.
5. Choose JPEG and EPSG:7844 — GDA2020, then click Add.
6. Set the project CRS to EPSG:7844 too. After adding collars below, right-click their layer and choose Zoom to Layer.

Alternatively, click New at step 2, name the connection Landgate Locate, and use:
https://public-services.slip.wa.gov.au/public/services/SLIP_Public_Services/Locate/MapServer/WMSServer
Leave username and password blank. Do not append GetMap-specific bbox or image-size parameters.

This public Landgate WMS does not require an ArcGIS Online account. QGIS and the web application can request the same service.
In the checked TBDD area the imagery index reports 0.5 m pixels, September 2010 and April 2011 flights, and 5 m positional accuracy.
Pixel size describes image detail, not collar accuracy. This is not 2025 or live imagery. Dates and resolution vary by location.
Changing to QGIS cannot turn the same 30 m Landsat source into high-resolution photography; detail depends on the source imagery.

2. Add exported collar results

1. Select holes, indicators and depths in the web application. Optionally set a condition and minimum continuous length, then click Update view.
2. Click Export result pack and extract the ZIP.
3. In QGIS, choose Layer > Add Layer > Add Delimited Text Layer.
4. Select holes.csv, CSV format, UTF-8 encoding and Point coordinates.
5. Set X to longitude, Y to latitude, and geometry CRS to EPSG:7844 — GDA2020.
   Do not assume EPSG:4326 merely because the columns contain longitude/latitude. The exported crs field records the source datum.
6. Click Add. Rows without coordinates cannot produce points, but remain in the CSV.
7. Right-click the point layer > Properties > Symbology. Categorise by status or use graduated symbols for total_length_m.
   Label by hole_id. Place the point layer above the imagery.

Each holes.csv row summarises one hole in the applied query:
hole_id: hole name.
longitude, latitude, crs: surface-collar position and datum.
run_count: continuous intervals meeting the condition.
total_length_m: their combined length in metres.
numeric_coverage_fraction: fraction of the requested depth window with numeric values, from 0 to 1; not model confidence.
status: computed query status, not mineral type.
query_id: identifier shared with the other exported tables.

Each intervals.csv row is an along-hole interval, without underground coordinates. Each evidence.csv row is a source-evidence record.
Load them as non-spatial tables and relate them using hole_id, query_id and run_id.
A hole may have many intervals: do not treat intervals.csv as a one-row-per-hole table for a one-to-one join.
Surface collars alone do not reconstruct underground trajectories or geological sections.

The export is a snapshot of an applied query. After changing conditions, export again and update QGIS. There is no live two-way synchronisation.
To retain styling and layers, save the data to a GeoPackage and save the QGIS project.

3. Reusable parts for a future plugin

The Python data registration, CSV parsing, metric definitions, coordinate validation, interval querying and export logic can be reused:
datasets.py, library.py, summaries.py, metrics.py, coords.py, engine.py, exports.py.

A plugin could add a QDockWidget containing hole selection, indicators, conditions and depth profiles, with QGIS handling basemaps and map selection.
It would still need selection links, query execution, layer updates and tests in the QGIS environment.
The HTML/JavaScript interface does not automatically become a native panel. The current deliverable is the web application plus the data and basemap connections described here.
Local installation is possible; official repository publication has separate metadata, licence and review requirements.
